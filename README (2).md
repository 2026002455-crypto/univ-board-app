# 🎓 학과 게시판 (3단계: 복합 다중 게시판)

바이브 코딩(AI 에이전트와의 대화)으로 개발한 **공간별 다중 게시판 웹앱**입니다.
HTML 파일 1개 + Supabase(인증·DB)로 동작하며, 별도 빌드 과정 없이 브라우저에서 바로 실행됩니다.

- 실행 파일: `board-stage-1.html` (필요하면 `index.html`로 이름을 바꿔 올리면 GitHub Pages로 바로 열 수 있습니다)
- 기술 스택: HTML / CSS / Vanilla JavaScript, [Supabase](https://supabase.com) (Auth, PostgreSQL, RPC)
- 폰트: IBM Plex Sans KR (Google Fonts)

## 1. 실행 방법

### 방법 A. 로컬에서 실행
1. 이 저장소를 내려받습니다.
2. `board-stage-1.html`을 브라우저로 엽니다. (인터넷 연결 필요 — Supabase, 폰트 CDN 사용)

### 방법 B. GitHub Pages로 실행
1. 저장소 → **Settings → Pages**
2. Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 설정
3. 파일 이름을 `index.html`로 올렸다면 `https://<계정>.github.io/<저장소>/` 로 접속

## 2. 테스트 계정

채점·확인용으로 미리 만들어 둔 계정입니다. 회원가입 없이 바로 로그인해서 기능을 확인할 수 있습니다.

| 구분 | 이메일(아이디) | 비밀번호 | 권한 |
|---|---|---|---|
| 🛡️ 관리자 | `admin@naver.com` | `123456` | 전체 관리자(`admin`) |
| 👤 일반 회원 | `testuser@naver.com` | `1234567` | 일반 회원(`user`) |

**관리자 계정으로 할 수 있는 일**
- 공간 생성·삭제 (관리자 탭)
- 모든 공간 접근, 공간별 회원 승인·정지·탈퇴 처리, 운영자 지정
- 게시판 추가·권한 설정, 공지사항 작성
- 비공개 글 열람 등 전체 시스템 통제

**일반 회원 계정 용도**
- 시스템 로그인 및 통합 테스트용 (공간 가입 신청 → 승인 → 글·댓글 작성 흐름 확인)

**추천 확인 순서**
1. `testuser@naver.com`으로 로그인 → **공간 가입** 탭에서 공간에 가입 신청
2. 로그아웃 후 `admin@naver.com`으로 로그인 → **공간 운영 → 회원 관리**에서 승인
3. 다시 `testuser@naver.com`으로 로그인 → **게시판** 탭에서 글·댓글·추천 확인
4. 관리자 계정으로 공지 등록, 비공개 글 열람, 회원 정지/해제 확인

> ⚠️ 위 계정은 **학습·채점용 테스트 계정**입니다. 공개 저장소에 비밀번호가 노출되므로 실제 사용하는 비밀번호나 개인정보는 절대 사용하지 마세요. 채점이 끝난 뒤에는 관리자 비밀번호를 변경하거나 계정을 삭제하는 것을 권장합니다.

## 3. 구현된 기능

### 계정 / 인증
| 기능 | 설명 |
|---|---|
| 회원가입 | 이름, 전화번호, 이메일, 비밀번호(6자 이상) 입력. 이메일 형식·필수값 검증 |
| 로그인 / 로그아웃 | Supabase Auth 이메일+비밀번호 방식 |
| 비밀번호 재설정 | 가입한 전화번호로 본인 확인 후 바로 재설정 (`reset_password_by_phone` RPC) |
| 회원정보 수정 | 이름·휴대폰 번호·비밀번호 변경 (이메일은 변경 불가) |
| 다크/라이트 테마 | 헤더 버튼으로 전환 (기본값 다크) |

### 공간(Space) 구조
- **공간 가입 탭**: 공간 목록을 보고 가입 신청 → 운영자 승인 대기(`pending`) → 승인(`approved`)
- 가입 신청 취소, 탈퇴 후 재가입 신청 가능
- 가입한 공간의 게시판만 열람·작성 가능 (전체 관리자는 모든 공간 접근)

### 게시판
| 기능 | 설명 |
|---|---|
| 카페형 레이아웃 | 좌측 사이드바(공간 → 게시판 트리) + 우측 게시글 목록 |
| 글쓰기 / 수정 / 삭제 | 제목 100자, 내용 입력. 작성자 본인 또는 운영자 권한 |
| 공지사항 | 운영자가 공지로 등록하면 목록 최상단 고정 |
| 익명 작성 | 체크 시 작성자가 "익명"으로 표시 |
| 비공개(비밀글) | 작성자 본인과 운영자만 열람, 그 외에는 "🔒 비공개 글입니다." 표시 |
| 검색 | 게시판 내 제목·내용 검색 |
| 페이지네이션 | 10개 단위 |
| 조회수 | 상세 열람 시 `increment_view` RPC로 증가 |
| 추천(좋아요) | 글당 1인 1회 토글, 추천 수 표시 |
| 댓글 | 등록(최대 300자) / 삭제 |

### 탭 구성
1. **전체 게시글** – 내가 가입한 공간 전체의 새 글 피드 (공간 필터 + 제목 검색, 상세·댓글 포함)
2. **게시판** – 공간별 게시판 열람·작성
3. **건의사항** – 공간과 관계없이 모두가 쓰는 공통 게시판 (내부적으로 `__global_suggestions__` 공간에 보관)
4. **공간 가입** – 가입 신청 / 상태 확인
5. **공간 운영** (운영자 전용) – 게시판 추가·이름변경·글쓰기 권한(전체/운영자만)·삭제, 게시판별 전담 운영자 지정, 회원 승인/거절/정지/정지 해제/탈퇴 처리
6. **관리자** (전체 관리자 전용) – 공간 생성·삭제

### 권한 체계
| 역할 | 할 수 있는 일 |
|---|---|
| 일반 회원 | 가입한 공간의 글·댓글 작성, 추천 |
| 공간 운영자 | 자기 공간의 게시판/회원 관리, 공지 등록, 비공개 글 열람 |
| 전체 관리자(`admin`) | 모든 공간 접근, 공간 생성·삭제 |
| 정지된 회원 | 해당 공간에서 읽기만 가능 (정지 안내 배너 표시) |

## 4. 데이터 구조 (Supabase)

코드에서 사용하는 테이블과 RPC입니다.

| 테이블 | 용도 |
|---|---|
| `profiles` | 회원 정보 (name, phone, role, status) |
| `spaces` | 공간 |
| `memberships` | 공간별 가입 상태 (role, status, left_at, suspension_reason) |
| `boards` | 공간별 게시판 (write_perm) |
| `board_operators` | 게시판 전담 운영자 |
| `posts` | 게시글 (is_notice, is_anonymous, is_private, view 수 등) |
| `post_likes` | 추천 (post_id, user_id) |
| `comments` | 댓글 |

| RPC 함수 | 용도 |
|---|---|
| `reset_password_by_phone` | 전화번호 기반 비밀번호 재설정 |
| `increment_view` | 조회수 증가 |
| `get_space_members` | 공간 회원 목록 조회 |
| `manage_space_member` | 회원 정지 / 정지 해제 / 탈퇴 처리 |

> ⚠️ **보안 참고**: 코드에 포함된 키는 Supabase의 *publishable(anon)* 키로, 공개 저장소에 올라가도 되도록 설계된 키입니다. 다만 **모든 테이블에 RLS(Row Level Security) 정책이 켜져 있어야** 안전합니다. `service_role` 키는 절대 코드에 넣지 마세요.

## 5. 개발 과정 (바이브 코딩)

### 진행 방식
1. 만들고 싶은 서비스를 자연어로 설명 → 에이전트가 HTML 단일 파일 + Supabase 구조 제안
2. 화면(탭)·기능 단위로 프롬프트를 나눠 점진적으로 추가
3. 브라우저에서 직접 실행해 보고, 동작이 어색하면 증상을 그대로 설명해 수정 요청
4. 최종적으로 가입 → 공간 가입 → 글쓰기 → 댓글/추천까지 직접 확인 후 제출

### 단계별 프롬프트와 에이전트 응답 요약

> 아래는 개발 과정에서 사용한 프롬프트의 **요지**와 에이전트 응답의 **요약**입니다.
> 실제 대화 원문이 있다면 각 단계의 "원문" 칸에 붙여 넣어 주세요.

#### 단계 1. 기본 게시판 + 회원 시스템
- **프롬프트 요지**: "HTML 단일 파일과 Supabase로 회원가입/로그인이 되는 게시판을 만들어줘. 글쓰기·수정·삭제·댓글·검색·페이지네이션이 있어야 해."
- **에이전트 응답 요약**: 로그인/회원가입 화면, 글 목록 테이블, 상세 보기, 댓글 영역을 구성하고 Supabase Auth와 `posts`, `comments`, `profiles` 테이블 연동 코드를 작성.
- **원문**: _(여기에 실제 프롬프트/응답 붙여넣기)_

#### 단계 2. 공간(Space) 개념과 카페형 레이아웃
- **프롬프트 요지**: "네이버 카페처럼 공간마다 여러 게시판이 있고, 공간에 가입 신청하면 운영자가 승인하는 구조로 바꿔줘."
- **에이전트 응답 요약**: `spaces`, `boards`, `memberships` 테이블을 추가하고 좌측 트리 사이드바, 공간 가입 탭, 승인 대기 상태 흐름을 구현.
- **원문**: _(여기에 실제 프롬프트/응답 붙여넣기)_

#### 단계 3. 운영자 / 관리자 기능
- **프롬프트 요지**: "공간 운영자가 게시판을 만들고 회원을 승인·정지·탈퇴시킬 수 있게 하고, 전체 관리자는 공간을 만들고 지울 수 있게 해줘."
- **에이전트 응답 요약**: 공간 운영 탭(게시판 관리, 회원 관리), 관리자 탭을 추가. 정지 사유 입력 모달, 게시판별 전담 운영자 지정, 권한별 버튼 노출 로직 작성.
- **원문**: _(여기에 실제 프롬프트/응답 붙여넣기)_

#### 단계 4. 글 옵션 · 전체 게시글 · 건의사항
- **프롬프트 요지**: "공지, 익명, 비밀글, 추천 기능을 넣고, 가입한 모든 공간의 새 글을 한눈에 보는 탭과 공간 상관없이 쓰는 건의사항 게시판을 만들어줘."
- **에이전트 응답 요약**: 글쓰기 폼에 체크박스 3종 추가, `post_likes` 테이블과 추천 토글, 전체 게시글 피드(공간 필터·검색), 공통 건의사항 게시판 자동 생성 로직 구현.
- **원문**: _(여기에 실제 프롬프트/응답 붙여넣기)_

#### 단계 5. 비밀번호 재설정 방식 수정
- **프롬프트 요지**: "비밀번호 재설정이 이메일 링크 방식으로 바뀌었는데, 가입한 전화번호를 입력하면 바로 재설정되는 방식으로 되돌려줘."
- **에이전트 응답 요약**: 이메일 링크 방식 코드를 제거하고, 전화번호 확인 후 비밀번호를 바꾸는 `reset_password_by_phone` RPC 호출 모달로 교체.
- **원문**: _(여기에 실제 프롬프트/응답 붙여넣기)_

### 개발하며 겪은 점 / 배운 점
- 한 번에 모든 기능을 요청하기보다 **탭 단위로 나눠 요청**하는 편이 결과가 안정적이었다.
- "안 돼요" 대신 **어떤 화면에서 무엇을 눌렀더니 어떤 메시지가 떴는지**를 알려 주면 수정이 빨랐다.
- 화면 코드만으로는 부족하고 **DB 정책(RLS)과 RPC 함수**가 함께 맞아야 동작한다는 점을 알게 되었다.
- 본 시스템은 본인확인을 하지 않는 학습용 프로젝트이며, 실서비스에는 추가적인 보안 검토가 필요하다.
